# 日和对话分寸：小样本诊断（2026-10-01）

这一轮修改默认人格的表达风格、行为边界与示例，不换大脑或声线。仍保留活泼、自己的稳定口味和轻微吐槽，但允许一句普通回应；分享、抱怨不自动触发建议；纠正她时先认清偏差；需要代码或知识时直接办事。只升级未改动的旧默认，自定义卡（包括空偏好）不覆盖。

## 真实样本与后续修订

原始比较是 4 个合成上下文 × 2 张卡，每张卡每个上下文只取一次真实 DeepSeek 回复。历史 assistant 句子是人工编写的夹具，只有每个 text 是这轮实际生成的回复，不能把历史夹具说成已测到的模型行为。

- 便利店：旧卡回复“两次都空手出来”，这是用户没提供的动作；初版新卡改成第三趟买饮料的回应，没有复现该动作。
- 不想解决也不想安慰：两版都没有继续拆论文步骤；不能将这项说成旧版失败、新版修好。新版另提了“想说点别的也行”，不等于用户真的想换话题。
- 被指出硬扯草莓：旧卡认错后叮嘱带伞；初版新卡认错后问天气感受。独立评审均未判这一对不合格；因此“追问更自然”或“带伞建议一定失败”没有得到这次复核支持。
- 只给代码：两版均只给同一段 Python 代码，没有额外陪聊。

随后发现初版新卡的菜单示例自己写了未提供的“十分钟”，先修示例。两条不同上下文的追加检查又暴露了常见剧情补造：找书回复加了“翻箱倒柜”，程序回复断言“昨天还好好的”。[这些输出](raw/post-review-new-cases.jsonl)与[当时的卡](post-review-card.json)全部保留，未算作成功最终验证。

最终卡再明确区分“共鸣”与“替用户写经历”，补了有依据的接梗/不拆步骤示例，并移除没有先前回复却声称“我刚才急着出主意”的示例动作。原比较[初版候选卡](candidate-card.json)与[最终上线卡](shipped-card.json)不同，早先盲审不能冒充最终卡的测评。

最终 6 次真实检查（[完整输出](raw/shipped-card-cases.jsonl)）包含上述两条复测及四条不同上下文：

- 找书：没有再写“翻箱倒柜”；回复仍含“会愣一下”这样的泛化情绪表达，不应当作用户已明确报告的感受。
- 吐槽报错：没有再写“昨天正常”，也没给调试步骤。
- 口味不同：仍表达喜欢草莓味，没有随用户讨厌草莓而改口；“才吃得下去”属于角色口味口语，不是实际吃过的证据。
- 两句解释缓存：实际是两句话，没有加陪聊尾巴。
- 明确不再追问：没有再问问题。
- 闹钟按掉又睡：虽没劝改作息，仍说“代价也是真的疼”并问“赶上了吗”，暗含用户有负面后果/要赶某件事。这是剩余问题，不算全通过；更自然的分寸仍需持续多轮验证。

## 独立匿名复核

采用冻结的[三项标准](rubric.md)与[配置](review-config.json)，先 prepare 生成不同匿名 ID/顺序与输入哈希，再由两个新建、无历史上下文的 agent 独立判断 8 条原比较回复。orchestrator 不投票。它们只见对应 packet 与定义，不见卡、版本映射或另一位意见。权重均为 1；无真人校准，不宣称某个 reviewer 更可靠。

| 维度 | 两位完全一致 | 分歧 |
| --- | --- | --- |
| register（分寸/助手腔） | 7/8 | 旧卡便利店回复：fits vs assistant_like |
| attunement（接话/边界） | 7/8 | 同一回复：fits vs misses |
| grounding（依据） | 8/8 | 无；同一回复均判 invented |

合计 22/24 字段两人一致，不是准确率。helper 输出 21 个 silver 字段、3 个 provisional 字段、0 个缺失字段。3 个 provisional 都来自上述有问题的旧回复（helper 对有 issue 的条目不会 auto-accept，包括双方一致的 invented）；“0 unresolved”不等于所有回复合格。

另做 1 条、仅 2 个分歧字段的盲审，未展示前两位的意见或身份：register=fits、attunement=misses。此单独意见仍是 provisional，不回填成双方一致，不改变原聚合。两个原分歧字段仍待真人判断；grounding 的问题按双方一致保留。

总计 16 个整条 reviewer assignment + 1 个 field-only assignment。原 8 项均有两位评价；字段盲审覆盖 1 项。小分层向上取整后校准重叠选了 3/8、固定随机审计 2/8。实际选中 ID 在[路由记录](routing-and-hashes.json)。这些是 AI 重叠与审计路由，不是已执行真人校准。

真人最终标签 = 0。建议人工复核队列：有问题的旧便利店回复 + 固定审计的旧代码-only与旧不劝建议回复，共 3 个不同条目；人工审计尚未执行。模型同源可能有相关偏差，agent 精确模型修订/token 数未暴露。独立原始 final 输出和规范化标签分开保留；不是 provider-native API 响应。

## 覆盖与复现边界

- 真实 DeepSeek 调用共 16 次：8 原比较 + 2 暴露补故事的新增检查 + 6 最终卡检查；预算扩展见两份 amendment。没有失败重采样或只保留好答案。
- health 报告/requested model 为 deepseek-flash；应用未暴露上游精确修订、provider-native token usage 或计费，不推测这些值。
- 原比较 baseline 仅保留旧 smoke CLI 输出的可见文本（trim 去掉外围空白），无原应用事件；之后的 runner 保留完整应用 NDJSON 事件，不是原始 provider 流。
- 原比较不是随机对照或 held-out benchmark，候选卡已看过旧版问题；最终补充检查也不是盲审/代表性抽样。不能用 4 对或 6 条证据推断总体人类自然度、消灭幻觉、语音表现或长期人格一致性。
- 新 runner 全批预检后串行请求；健康未配置、错误事件、缺 done、空回复、HTTP/网络失败、乱码 NDJSON 均导致非零退出。可解析错误事件先留证，再停止剩余请求。测试 fake-fetch，不消耗 API。
- 本轮无语音模型训练、音色克隆、ASR 或新增自动记忆。prompt 是倾向，不是硬保证。

可用 skill helper 对原 8 项重复 prepare/aggregate；路径参数采用本目录中的 items.jsonl、review-config.json、run/reviews。prepare 应先于任何 reviewer，不用最终追加样本混入原比较。散列与独立生成/复核身份限制在 routing-and-hashes.json、reviewer-provenance.json；raw 目录保留原输出。
